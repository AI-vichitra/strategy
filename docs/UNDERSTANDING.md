1. **No agent-as-data registry / catalog (L1).** Every one of the 24 agents' identity lives as parallel, independently-edited string literals across at least 5 places that must be kept in sync by hand: `TemplateGrid.tsx:26-155` (`allTemplates`), `MainContent.tsx:27+` (`agentQuestions`), `MainContent.tsx:540-590` (`agentPrompts`), `MainContent.tsx:597` (`homeAgentTitles`), and `chat.py:22-48` (`questions_map`) — plus the `if/elif` chain in `ai_service.py:388-581`. This blocks every other gap below, because adding or fixing any one agent means editing multiple unsynchronized places at once. Effort: **weeks** — not because the registry itself is hard, but because migrating 24 agents' worth of scattered, already-inconsistent data without silently dropping behavior requires reconciling all 5+ sources agent-by-agent.
2. **No research/connector layer beyond Tavily + Instagram (L3).** 0 of the ~20 named connectors (Firecrawl, Exa, Ahrefs, GSC, Semrush, SerpAPI, HubSpot, Salesforce, GA4, LinkedIn, Reddit, Google Ads, Apollo, etc.) exist as live integrations (Section 1 table). Effort: **weeks per connector** (each is a distinct third-party API/OAuth integration) — this is the largest single effort item of the five.
3. **No output validation gate (L7).** None of SYSTEM_CORE's own stated rules are enforced in code (3C table above) — the model can violate every rule it's given and nothing catches it; charts can be malformed and the frontend will still render whatever it can parse. Blocks any agent count scaling confidently, since quality currently depends entirely on the model happening to comply. Effort: **days to low-weeks** for a basic structural check (required sections present, chart JSON schema), more for a repair-pass loop.
4. **No token budgeting on retrieved context (L5).** `_format_context` concatenates all 6 retrieved chunks with no length cap (`backend/services/ai_service.py:335-350`); nothing ranks or truncates by `(agent.id + user answers)` as FULL_PICTURE §5 specifies. Blocks reliable behavior once a brand's KB grows large enough that 6 chunks × 500 words risks pushing past a model's effective context window or drowning the signal — not an immediate crash risk today given `TOP_K=6`, but a silent quality risk as KB size grows. Effort: **days**.
5. **Questionnaire answers never reach the prompt as structured facts (L2/L5).** Confirmed in 3C: the dedicated `questionnaire_answers` DB column is dead, and the actual mechanism (unlabeled text appended to the chat box) means the model receives the user's answers mixed into a single free-text user turn rather than as the clean "Primary SEO objective: More Leads"-style facts FULL_PICTURE's Block 3 calls for. This directly degrades the only 3 "complete" agents today, since their own prompts explicitly reference "the user's specific answers to the N setup questions" (e.g. `backend/services/ai_service.py:450-451` for GTM Strategy) — which the model receives in a weaker form than the prompt assumes. Effort: **days** for the plumbing itself, though it depends on gap #1 (a real per-agent question schema) to do properly rather than as another one-off patch.
